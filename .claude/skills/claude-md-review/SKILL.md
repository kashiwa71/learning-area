## 指示

上の `CLAUDE.md` を、次の四つの分類で一行ずつ判定する。判定した結果だけを報告し、
ユーザーが選ぶまでファイルを書き換えない。

1. **残す**：コードを読んでも分からず、毎セッション必要な情報。コマンド、環境の前提、
   既定と違う規約、設計判断、落とし穴。
2. **削る**：エージェントがコードやファイル一覧から読み取れる情報。ディレクトリ構成、
   依存パッケージの列挙、言語の標準的な作法、「読みやすく書く」のような一般論。
3. **スキルへ移す**：手順として書かれていて、毎回は使わないもの。番号付きの作業手順、
   リリースやデプロイの段取り。
4. **ルールへ移す**：特定の種類のファイルにだけ効く規約。`.claude/rules/` に
   `paths` 付きで置き直す候補として、パターンも併せて提案する。

続けて次を点検する。

- **矛盾**：`CLAUDE.md` の中、および `.claude/rules/` の各ファイルとの間で、
  反対のことを言っている箇所を挙げる。
- **曖昧さ**：従ったかどうかを判定できない書き方の行を挙げ、検証できる形の書き換え案を添える。
- **強調の乱用**：`IMPORTANT` や「必ず」が複数箇所にあれば指摘する。強調は一、二箇所までに絞る。
- **機構に移すべきもの**：例外を許さない要求（整形、リント、テストの実行、触らせないパス）は、
  フックか権限ルールの候補として挙げる。

報告は次の形で出す。

```text
残す:   N 行
削る:   N 行  ← 一覧と、削ってよい理由を一行ずつ
移す:   N 行  ← 移し先（スキル / ルール）と、その名前の案
矛盾:   一覧
曖昧:   一覧と書き換え案
```

最後に、削減後の見込み行数を示す。200 行を超えたままなら、何をさらに移せるかを一つ提案する。
