# 教材と演習の書き方

`docs/` と `exercises/` のファイルを編集するときの決まり。読者は、これから自分のプロジェクトを
立ち上げる開発者で、Claude Code は入っているが設定ファイルは書いたことがない、と想定する。

## 教材ページの形

- 冒頭は、その回で扱う問題の提示から入る。目次や「この章で学ぶこと」の列挙を置かない。
- 見出しは `##` から始める。`###` は必要なときだけ使い、四階層目は作らない。
- 仕様（フロントマターの項目名、フックのイベント名、権限ルールの文法）を書くときは、
  https://code.claude.com/docs/ の該当ページを確認してから書く。確認できなかったものは書かない。
- 表は、比較か対応関係があるときだけ使う。単なる列挙には箇条書きを使う。
- コードブロックには言語を指定する（`json`、`bash`、`markdown`、`text`）。
- 末尾に、対応する演習へのリンクを置く。演習が無い回は置かない。

## 演習ページの形

次の三節を必ずこの順で持つ。

1. `## 課題`：何を作るか。完成物を一文で示す。
2. `## 進め方`：手順。番号付きの箇条書きにする。
3. `## できたと言える条件`：チェックボックス `- [ ]` の並び。自分で判定できる項目だけを書く。

「できたと言える条件」に、判定が主観になる項目を書かない。
「読みやすくなっている」ではなく「`./scripts/check.sh` が終了コード 0 を返す」のように書く。

## リンク

- 教材どうしは相対パスで結ぶ（`03-rules.md`、`../.claude/settings.json`）。
- 新しい教材を足したら `README.md` の表にも行を足す。演習も同様。
- リンク切れは `./scripts/check.sh` が検出する。追加したら実行して確認する。

## 用語

同じものを別の言い方で呼ばない。この教材では次の語で通す。

- **エージェント**：Claude Code 本体。「AI」「ツール」と呼び換えない。
- **サブエージェント**：`.claude/agents/` で定義する、別コンテキストで動くもの。
- **スキル**：`.claude/skills/<名前>/SKILL.md`。「コマンド」と呼ばない。
- **ルール**：`.claude/rules/` に置く、パスで絞れる規約。
- **フック**：設定で登録し、決まった時点で必ず走るシェルコマンド。
