# 演習 01：CLAUDE.md を書く

対応する教材：[CLAUDE.md の書き方](../../docs/02-claude-md.md)

## 課題

自分が普段さわっているプロジェクトを一つ選び、そこに 40 行以内の `CLAUDE.md` を書く。
書いた後、その内容が実際にエージェントの動きを変えることを確認する。

適当なプロジェクトが無ければ、小さなものを新しく作ってよい。README しか無いリポジトリでも成立する。

## 進め方

1. プロジェクトのルートで `claude` を起動し、`/context` を実行する。
   Memory files に何も出ていないことを確かめる。この状態が出発点になる。

2. `CLAUDE.md` を手で書く。次の三つだけを入れる。
   - 何をするプロジェクトか（一、二文）
   - 繰り返し使うコマンド（テスト、ビルド、リント、ローカル実行）
   - 既定と違う規約、または触ると壊れる場所

3. エージェントがコードを読めば分かることが混ざっていないか読み返す。
   ディレクトリ構成の一覧、依存パッケージの列挙、言語の標準的な作法が入っていたら消す。

4. `claude` を再起動して `/context` を実行し、Memory files に `CLAUDE.md` が出ることを確認する。

5. 書いた規約に関係する作業を一つ頼み、指示なしでその規約に従うかを見る。
   たとえば「テストを走らせて」とだけ言って、書いておいたコマンドが使われるかを確かめる。

## できたと言える条件

- [ ] `CLAUDE.md` がプロジェクトのルートにあり、40 行以内である
- [ ] `/context` の Memory files に `CLAUDE.md` が出ている
- [ ] 書いた各行について、「無いとエージェントが誤るか」に yes と答えられる
- [ ] ディレクトリ構成の一覧と依存パッケージの列挙が入っていない
- [ ] 手順 5 で、書いた規約に沿った動きが一度は観察できた

## つまずいたら

`/context` に出ない場合は置き場所が違う。作業ディレクトリか、その上位に置く必要がある
（[置き場所](../../docs/02-claude-md.md#置き場所)）。

書くことが思い付かない場合は、直近そのプロジェクトでエージェントに出した訂正を思い出す。
同じ訂正を二回打っていれば、それが最初の一行になる。
