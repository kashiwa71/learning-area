# 演習 04：検証ループを閉じる

対応する教材：[仕事の進め方](../../docs/08-workflow.md)

## 課題

同じ実装を二回、条件を変えて依頼し、結果の差を観察する。
一回目は検証手段を渡さず、二回目は渡す。

## 進め方

1. 空のディレクトリで `claude` を起動する。

2. **検証手段なし**で依頼する。

   ```text
   メールアドレスを検証する validateEmail 関数を書いて
   ```

   出てきた実装を保存し、`before.js` などの名前を付けておく。

3. `/clear` する。文脈を残したまま二回目に進むと、比較にならない。

4. **検証手段あり**で依頼する。

   ```text
   validateEmail 関数を書いて。判定は次のとおり。
   user@example.com は true、invalid は false、user@.com は false、
   user@example は false、"a b"@example.com は true。
   テストを書いて実行し、全部通るまで直して。
   ```

5. 二つの実装を比べる。次の入力で両方を試す。

   ```text
   ""、"a@b.c"、"user@.com"、"user@@example.com"、"user name@example.com"
   ```

6. 一回目の実装が誤る入力を見つけ、なぜ一回目には見つからなかったのかを説明できるようにする。

## できたと言える条件

- [ ] 二つの実装ができていて、二回目にはテストが付いている
- [ ] 二回目のテストが実際に実行され、通っている（出力を確認した）
- [ ] 一回目の実装が誤る入力を、少なくとも一つ挙げられる
- [ ] 二回目でエージェントが自分でテストを直した回数を答えられる

## 次の一歩

`Stop` フックにテストの実行を仕込み、落ちている間はターンを終えられないようにする
（[フック](../../docs/06-hooks.md)）。依頼文で毎回「テストを走らせて」と書く必要が無くなる。

ただし連続して 8 回止めると Claude Code 側が打ち切る。無限に粘らせる仕組みではない。
