# 演習 03：最初のスキルを作る

対応する教材：[スキル](../../docs/04-skills.md)

## 課題

自分のプロジェクトで、`/` から呼び出せるスキルを一つ作る。
シェルコマンドの出力を本文に埋め込む形にして、呼び出した時点で状況が渡るようにする。

題材は何でもよい。決まらなければ「未コミットの変更からコミットメッセージの案を出す」を作る。

## 進め方

1. 直近一週間で、同じ趣旨の依頼を二回以上チャットに打った作業を思い出す。それが題材になる。

2. ディレクトリと `SKILL.md` を作る。ディレクトリ名がコマンド名になる。

   ```bash
   mkdir -p .claude/skills/my-skill
   ```

3. フロントマターに `description` を書く。何をするかと、いつ使うかの両方を入れる。
   主な用途を先頭に置く（一覧の中で 1,536 文字に切り詰められるため）。

4. 本文に、`` !`コマンド` `` の形で状況を埋め込む。
   `git diff HEAD`、`git status --short`、`ls`、テストの実行結果など。

5. 続けて指示を書く。何をするかだけを書き、なぜそうするかの説明は入れない。
   一度読み込まれた本文はセッション中ずっと残る。

6. `claude` を起動して `/my-skill` を打ち、動くことを確認する。

7. 次に、スキル名を打たずに、`description` に書いた状況に当てはまる依頼をしてみる。
   自動で読み込まれるかを見る。読み込まれなければ `description` を書き直す。

## できたと言える条件

- [ ] `.claude/skills/<名前>/SKILL.md` があり、`/<名前>` で呼び出せる
- [ ] `description` に、何をするかと、いつ使うかの両方が書かれている
- [ ] `` !`コマンド` `` を使っていて、呼び出すと実際の出力が埋め込まれている
- [ ] 本文が 50 行以内である
- [ ] スキル名を打たずに依頼したときも読み込まれる（あるいは、読み込ませたくないので
      `disable-model-invocation: true` を付けたと説明できる）

## 次の一歩

引数を受け取る形に変える。`$ARGUMENTS` を本文に置き、`/my-skill 引数` で渡す。
位置で取るなら `$0`、`$1`、名前で取るならフロントマターに `arguments` を宣言する。

副作用のある作業（デプロイ、本番への変更）に育ったら `disable-model-invocation: true` を付ける。
エージェントの判断で始まっては困るものは、手で打ったときだけ動くようにする。
