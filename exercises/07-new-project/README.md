# 演習 07：新規プロジェクトを立ち上げる

対応する教材：[新規プロジェクトの立ち上げ](../../docs/09-new-project.md)

## 課題

空のディレクトリから始めて、エージェントに任せられる状態のリポジトリを作る。
作るものは小さくてよい。ここで練習するのは、アプリケーションの中身ではなく、
立ち上げの順序である。

題材が決まらなければ「CSV を読んで集計結果を JSON で出す CLI」を作る。

## 進め方

順序を守る。後ろの段階を先にやると、まだ起きていない問題への対策を書くことになる。

1. **検証手段を作る**。ディレクトリを作り、`git init` して、言語ごとの初期化をする。
   失敗するテストを一つ書き、実際に落ちることを確認する。
   この時点で、合否を終了コードで返すコマンドが一つある状態になる。

2. **権限を許可する**。[templates/settings.json](../../templates/settings.json) を
   `.claude/settings.json` にコピーし、手順 1 のコマンドに合わせて書き換える。

3. **CLAUDE.md を書く**。[templates/CLAUDE.md](../../templates/CLAUDE.md) をコピーし、
   角括弧を埋める。埋められない項目は消す。40 行以内に収める。

4. **.gitignore を確認する**。`CLAUDE.local.md` と `.claude/settings.local.json` を足す。

5. **確認する**。`claude` を起動し、`/context` で `CLAUDE.md` が読み込まれていること、
   `/permissions` で許可が入っていることを見る。

6. **任せてみる**。手順 1 で落としておいたテストを渡し、「これを通して」と依頼する。
   途中で承認を求められた回数を数える。多ければ、手順 2 の許可が足りていない。

## できたと言える条件

- [ ] 一つのコマンドでテストが走り、終了コードで合否が分かる
- [ ] そのコマンドが `.claude/settings.json` の `allow` に入っている
- [ ] `.env` などの秘密が `deny` に入っている
- [ ] `CLAUDE.md` が 40 行以内で、コードを読んでも分からない情報だけが書かれている
- [ ] `CLAUDE.local.md` と `.claude/settings.local.json` が `.gitignore` に入っている
- [ ] `/context` に `CLAUDE.md` が出ている
- [ ] 手順 6 で、承認を求められた回数が 3 回以下だった

## 対話で進める場合

このリポジトリの `.claude/skills/new-project-setup/` を新しいプロジェクトにコピーして
`/new-project-setup` と打つと、同じ順序を聞き取りながら進めてくれる。

自分で一度やってからスキルを使うほうがよい。どの判断をスキルに任せているかが分かる。

## この後にやらないこと

フックとサブエージェントは、この段階では作らない。
守られない規約が実際に出てきてからフックへ、調査とレビューの頻度が上がってから
サブエージェントへ、という順で足す。
