# 演習 02：CLAUDE.md を刈り込む

対応する教材：[CLAUDE.md の書き方](../../docs/02-claude-md.md)

## 課題

このディレクトリの [bloated-sample.md](bloated-sample.md) は、よくある形に膨らんだ `CLAUDE.md` である。
これを、残す行だけの短い版に作り直し、削った行それぞれの行き先を決める。

行き先は四つある。消す、スキルに移す、ルールに移す、フックに移す。

## 進め方

1. `bloated-sample.md` を読み、一行ずつ次のどれかに分類する。

   - **残す**：コードを読んでも分からず、毎セッション必要な情報
   - **消す**：エージェントがコードやファイル一覧から読み取れる情報
   - **スキルへ**：手順として書かれていて、毎回は使わないもの
   - **ルールへ**：特定の種類のファイルにだけ効く規約
   - **フックへ**：例外を許さず、機械で判定できる要求

2. 残すと決めた行だけを集めて、新しい `pruned.md` を書く。

3. スキルへ移すと決めた部分を、`SKILL.md` の形（フロントマターと本文）で書き出す。
   ファイル名は `skill-draft.md` でよい。

4. `IMPORTANT` が四箇所ある。どれを残すかを一つだけ選び、残りをどう扱ったかを説明できるようにする。

5. 答え合わせとして、このリポジトリの `/claude-md-review` スキルに同じ判定をさせ、
   自分の分類と突き合わせる。一致しない箇所について、どちらが正しいかを考える。

## できたと言える条件

- [ ] `pruned.md` が 40 行以内に収まっている
- [ ] 消した行について、「エージェントが自分で調べられる」と説明できる
- [ ] リリース手順が `skill-draft.md` に移っている
- [ ] React とコンポーネントに関する規約が、`paths` 付きルールの候補として挙がっている
- [ ] `IMPORTANT` が一箇所以下になっている
- [ ] `npm run lint` の実行が、指示ではなくフックの候補として挙がっている

## 考えどころ

「テストはとても重要です」の段落は、削ってよいのか。判断の根拠は
「この行が無いとエージェントは誤るか」である。テストを書かせたいなら、
書かせる仕組み（フック、あるいは依頼文での指定）が要る。重要だと書いても書かれるとは限らない。

`## API について` の段落は、一部が残り、一部が消える。どこが境目になるかを説明できるとよい。
