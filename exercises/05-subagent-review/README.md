# 演習 05：サブエージェントにレビューさせる

対応する教材：[サブエージェント](../../docs/05-subagents.md)

## 課題

読み取り専用のレビュアーを一つ定義し、自分が書いた差分を点検させる。
本体のコンテキストがどれだけ節約できたかも確認する。

## 進め方

1. [templates/agents/code-reviewer.md](../../templates/agents/code-reviewer.md) を、
   自分のプロジェクトの `.claude/agents/code-reviewer.md` にコピーする。
   角括弧の箇所を自分のプロジェクトの内容に合わせる。

2. `tools` に `Edit` と `Write` が入っていないことを確かめる。
   このエージェントは指摘を返すだけで、書き換えられない。

3. 何か小さな変更を実装する。テストが落ちる程度の不備をわざと一つ残しておくとよい。

4. `/context` を実行し、その時点のコンテキストの使用量を控える。

5. レビューを依頼する。

   ```text
   code-reviewer サブエージェントで、直近の変更をレビューして。
   指摘は正しさと、明示した要件に関わるものだけにして。
   ```

6. 返ってきたら、もう一度 `/context` を実行して使用量を比べる。
   サブエージェントが読んだファイルが本体に載っていないことを確認する。

7. 同じ変更を、サブエージェントを使わずに本体で直接レビューさせ、
   `/context` の増え方を比べる。

## できたと言える条件

- [ ] `.claude/agents/code-reviewer.md` があり、`tools` が読み取り系だけに絞られている
- [ ] 呼び出して指摘が返ってきた
- [ ] 手順 3 で仕込んだ不備が指摘に含まれている
- [ ] 手順 6 と手順 7 のコンテキスト増加量の差を数字で答えられる
- [ ] レビュアーがファイルを書き換えていない（`git status` で確認した）

## 考えどころ

指摘の中に、正しさに関わらないものがいくつ混ざっていたかを数える。
指摘を探せと言われたレビュアーは、問題が無くても何かを指摘する。
依頼文の最後の一文（「正しさに関わるものだけ」）を外して同じことを頼み、
指摘の数と質がどう変わるかを見ると、その一文の効き目が分かる。
